# TraceRisk 项目改造计划书

日期：2026-11-08  
状态：已按本计划开展实施；实际代码、运行结果与未达成门槛见文末实施记录，不能将计划条目直接视为已通过。

## 1. 项目定位与目标

项目名称沿用 TraceRisk，业务描述为“面向中小企业授信前调查的可追溯风险分析助手”。主要使用者为金融机构调查人员和复核人员，企业是被调查对象。首期聚焦企业信息整理、风险初筛和调查报告，不承担授信额度计算、贷款审批或违约概率预测。

核心价值：将企业资料整理为有证据依据的风险发现，以固定规则提供可复算评分，通过人工复核形成可追溯报告。拟验证的业务收益是减少资料整理和核查时间；目前没有真实机构效率提升结论。

目标交付：一个能完整演示、能解释评分与证据、能正确处理缺失和冲突信息的比赛版本，配套数据说明、评测结果和五分钟答辩案例。

## 2. 现状与改造范围

依据现有 README、规则规范、证据契约、演示脚本及真实模型挑战评测文档梳理。历史验收记录不等于本次重新执行测试。

| 内容 | 当前基础 | 本轮方案 |
|---|---|---|
| 调查流程 | 企业选择、基准日、调查执行、复核、报告 | 保留流程，明确授信前调查场景 |
| 规则评分 | 四条确定性规则、版本与证据留存 | 保留算法，补足用户可读的评分说明 |
| AI 分析 | 检索、生成、引用与结构化支持校验 | 强化证据展示，验证真实模型端到端路径 |
| 人工复核 | 批准、修改、驳回及历史记录 | 保留机制，明确进入复核的原因 |
| 企业风险画像 | 企业详情、风险、证据等信息已分布在现有页面 | 在现有详情和报告中组织成统一摘要 |
| 数据 | 合成数据；真实外部数据接入未验证 | 首期保留合成基准，下一阶段验证人工审核的授权样本导入 |
| 真实模型 | 已有40条手工合成挑战样本实验 | 修正漏复核问题，再开展独立样本评测；不把小样本结果当业务准确率 |

本轮不建设全行业企业数据库、不承诺实时数据采集、不新增自动放贷、融资撮合、实时预警或复杂自学习评分模型。不新增技术框架，复用 Vue 3、FastAPI、PostgreSQL 和现有工作流。

## 3. 业务方案

### 3.1 主流程

选择企业及调查基准日 → 检查数据来源覆盖 → 规则评分与证据分析 → 校验 AI 输出 → 判断是否需要复核 → 生成报告。

上述规则评分与证据分析是业务分工，不要求改成并发执行。

高风险、来源不足、证据冲突、模型证据不足或建议复核等情况进入人工复核，其余有效结果可直接形成报告。引用硬校验失败时，不能用人工复核绕过校验或输出成功报告；明确显示失败原因和可执行的后续操作。

### 3.2 规则分析

| 规则 | 命中条件 | 分值 |
|---|---|---:|
| 司法 | 存在未结案件 | 35 |
| 经营 | 调查基准日仍有效的经营异常 | 25 |
| 新闻 | 基准日前含当日365天内至少两条独立负面报道 | 20 |
| 知识产权 | 核心专利失效或存在权属争议 | 15 |

每条规则每次调查最多计分一次，总分最高95；0～29、30～59、60～95分别为现有演示规则的低、中、高等级。不同转载不自动视为独立报道。缺少事实不作为负面命中，来源不足单独显示并触发复核。规则、基准日、命中事实及证据保留快照。AI 与复核人员不能修改分数。

这些权重是演示配置，不是金融机构认可的信用标准，不解释为违约概率。首期不重调权重；未来只有获得业务样本和专家评审后才另行研究。

### 3.3 AI 辅助分析

1. 从当前企业、当前调查允许使用的证据中，按风险类型检索相关片段。
2. 保存本次检索集合与内容版本，后续分析和复核使用同一集合。
3. 模型输出风险类型、标题、摘要、说明、证据引用和证据充分性等结构化内容。
4. 校验企业归属、引用范围、内容版本、原文摘录，以及预定义声明与结构化事实的一致性。
5. 对不能确定支持程度的自然语言扩展保守处理，进入人工复核；不宣称完成全部语义事实核验。

AI 的价值是辅助阅读、整理和表达证据。默认 Mock 演示与真实模型运行必须清楚区分；真实模型调用失败时明确提示，不静默替换成模拟结果。

### 3.4 企业风险画像与报告

优先复用现有页面，新增或整理以下信息区块：企业身份与调查日期、四类风险命中情况、规则分数及计算说明、来源覆盖与缺失提示、AI 风险发现及证据入口、复核状态和最终报告入口。

每条风险发现应能打开对应原文片段，并展示实际存储的来源和时间信息。展示风险分数时同时展示证据覆盖状态，避免把信息不足的零分误读为安全。

报告保留规则结果、原始 AI 发现、人工决定、最终发现、证据及版本信息。只增加帮助调查人员判断的内容，不建设新仪表盘或无实际用途的图表。

## 4. 数据落地方案

### 第一阶段：比赛版本

继续使用现有合成企业和证据，覆盖正常、规则命中、同名干扰、冲突、来源缺失等场景。页面、报告、答辩材料均标注合成数据。数据模拟工商、司法、新闻和知识产权资料形态，不表述为已接入真实服务。

### 第二阶段：小范围样本验证

优先采用研究团队能够合法使用的公开资料或经授权提供的样本，由人工先核对，再通过固定 JSON 模板和导入脚本进入独立验证环境。不先建设爬虫、通用文件解析平台或自动 OCR 链路。

样本至少记录：企业标识、来源名称与可用的原始地址、取得时间、信息有效日期、原文、风险类型、结构化事实及使用依据。缺失字段和不可用来源必须明确标记。新闻独立事件标识、核心专利标记等关键字段先由人工确认，不交由模型无依据推断。

样本来源、访问条件、使用权限和持续更新能力均属待落实项。不假设已经取得银行内部数据或商业数据库接口。若条件无法满足，比赛版本仍使用合成数据，真实数据试点保持未完成状态。

## 5. 实施阶段与交付物

以下为工作量估计，不是交付承诺；一个熟悉现有项目的开发者约需10～15个工作日，外部授权与业务访谈时间另计。

| 阶段 | 估计 | 实际任务 | 验收结果 |
|---|---|---|---|
| P0 定位统一 | 1～2日 | 统一 README、界面说明、答辩口径；整理现有与规划能力 | 所有材料服务对象一致，模拟与真实能力无混淆 |
| P1 画像整理 | 3～4日 | 在现有详情/报告展示评分说明、来源覆盖、风险与证据；补充复核原因 | 能从摘要进入证据；缺数据零分有明确警示；旧流程仍可用 |
| P2 模型与复核验证 | 4～6日 | 检查真实模型配置及端到端路径；分析已知漏复核；修复后增加未用于调参的验证案例 | 固定关键回归案例通过，真实结果单独记录，失败不输出伪成功报告 |
| P3 比赛交付 | 2～3日 | 固定演示数据与脚本，整理评测和备用截图，录制讲解 | 五分钟完成典型调查；能演示证据冲突或缺失的处理 |
| P4 真实样本试点 | 条件具备后另估 | 小规模人工审核样本导入、用户试用及耗时记录 | 可追溯至实际样本来源，报告实际失败与耗时，不外推整体效果 |

推进顺序为 P0 → P1 → P2 → P3；P4 以数据使用条件满足为前提。实施时每阶段拆分小任务，先检查对应现有代码，避免重复建设。

## 6. 验收与评测

### 必须通过的功能检查

- [ ] 同一规则、事实和基准日可复算出相同分数；重复案件和转载不重复计分。
- [ ] 已结案件不能被接受为未结案件的支持证据；跨企业和未检索引用被拒绝。
- [ ] 证据冲突与来源不足正确触发复核；零分不能掩盖来源缺失。
- [ ] 复核批准、修改、驳回均保留原始结果；人工不能改规则分数。
- [ ] 报告保持不可变，重复提交或恢复不生成不一致结果。
- [ ] 真实模型模式能完成调查、校验、必要复核与报告；模型失败有明确状态。
- [ ] 页面与报告清楚区分合成样本、模拟模型与真实调用。

回归沿用现有八类 E2E 路径，涉及新增展示时补充相应前端检查。文案调整不新增镜像测试。运行现有检查前遵守仓库数据库隔离要求，不改动保留库。

### 模型评测

现有40条合成挑战样本用于问题定位和回归，另增加约20条未参与调参的验证案例。分别统计引用合法性、结构化输出成功率、应复核案例召回情况、误复核情况、失败原因、延迟及实际调用成本。固定关键案例不得漏复核；其他结果完整披露，不用“全部正确”或单一准确率概括能力。

历史挑战评测记录的漏复核问题需优先处理。仅减少人工复核数量不能作为改进成果；必须同时检查是否漏掉应复核案例。标签先由团队复查，存在争议的案例记录理由；未有领域专家参与时明确说明限制。

### 业务效果验证

条件具备后，让试用者针对相同资料分别完成手工流程与辅助流程，平衡操作顺序，记录资料整理耗时、核查耗时、纠错次数和遗漏情况。报告样本数、参与者背景和测量方法。没有真实测量前，不写“效率提升50%”等数字。

## 7. 项目特色与对外表述

推荐描述：TraceRisk 面向金融机构的中小企业授信前调查，将企业资料转化为带证据依据的风险发现，通过规则评分、AI 辅助分析和人工复核，形成可追溯的调查报告。

重点展示：规则分数可复算；风险发现关联本次调查证据；冲突和信息缺失显式呈现；人工处理与最终报告保留记录。

这些是本项目的设计特色，不宣称竞争产品均不具备。商业模式暂作为机构工具试点的假设，待用户访谈验证；本轮不加入收费、订阅或采购功能。

## 8. 主要依赖与取舍

| 问题 | 处理方式 |
|---|---|
| 数据来源尚未落实 | 先完成合成比赛版本，真实样本另设准入条件 |
| 规则权重缺乏业务验证 | 保留演示标记，不宣称信贷预测能力 |
| AI 推理可能超出证据 | 引用与结构化校验、保守复核、记录失败；不承诺消除幻觉 |
| 已有真实模型评测存在漏复核 | 优先修正路由和验证，不把复核率下降等同安全性提高 |
| 工期有限 | 复用已有页面与流程，暂缓实时预警、动态评分与全量数据采集 |

最小完整交付是“定位清楚的既有流程＋可读的企业风险画像＋真实模型边界验证＋可复现答辩案例”。与重建评分系统相比，此方案改动较小，能直接利用现有证据与复核能力；代价是首期无法证明真实金融业务效果，需通过后续样本试点补足。
