# Task 2.2：一家企业和一条规则

日期：2026-09-11。合成数据，仅供演示。

## 任务契约

| 项目 | 约定 |
|---|---|
| 输入 | 企业 ID、调查基准日、司法来源的结构化案件状态证据 |
| 输出 | `JUDICIAL_OPEN_CASE_V1` 规则评估；命中时保存一条 35 分快照 |
| 数据变化 | 迁移 0004 新增 companies、evidence、rule_findings 与 rule_finding_evidence |
| 数据约束 | 企业合成键和信用代码唯一；证据来源 URI 在企业内唯一；每 Run 每规则唯一；证据引用绑定 ID 与内容哈希 |

| 幂等要求 | 合成数据脚本重复运行保留已有记录；相同规则快照重复保存返回原记录 |
| 范围 | 一家合成企业、司法证据和一条确定性规则；其余企业、规则、来源覆盖和冲突数据留给阶段 3 |

## 企业与证据故事

合成企业“华辰智造（合成演示）有限公司”使用固定、明确标为合成的 ID 和信用代码。故事包含三条司法证据：同一案件的两次未结状态记录，以及另一案件的一条未结状态记录。正文采用 SHA-256 哈希，Evidence 保存企业、来源、风险类型、观察日期、事实类型、案件号、状态、方向和来源 URI。

`scripts/seed_synthetic.py` 使用固定数据和冲突时不更新策略。重复运行不会重置已有记录；初始化完成后脚本会实际读取数据库执行规则，必须得到两个去重案件和一次 35 分命中，否则报错。

## 规则与快照

`JUDICIAL_OPEN_CASE_V1` 版本为 `1`，分值固定 35。规则只读取当前企业、司法来源、司法风险类型且 `fact_type=judicial_case_status` 的证据。它排除基准日后的记录，按案件号选择截至基准日的最新状态，至少一项最新状态为 `open` 时命中。

多个案件以及同案重复证据只扩充事实范围，不累加分数。快照参数保存基准日、目标状态、最小案件数、去重键和状态选择口径；命中事实键独立保留在评估结果中。持久化层以 `UNIQUE(run_id, rule_code)` 保证单次命中，并通过组合外键将引用的 Evidence ID 和内容哈希绑定到同一证据版本。

同一结果重放返回原快照。相同 Run 和规则编码若得到不同版本、分数、参数或证据引用，则抛出冲突而不改写历史结果。规则零分时不伪造命中记录。

## API

`GET /companies` 返回已登录用户可读的合成企业列表及“合成数据，仅供演示”提示；`GET /companies/{id}` 返回企业详情。analyst、reviewer、admin 均可读取，未登录返回 401，不存在的企业返回 404。本任务没有增加企业写接口。

## 运行

在项目根目录执行：

```powershell
uv run --directory apps/api alembic upgrade head
uv run --project apps/api python scripts/seed_synthetic.py
```

规则的纯函数与数据库读取、快照保存分开，便于独立验证日期、去重和计分，也避免测试规则时依赖数据库。
