# TraceRisk 五分钟截图讲解稿

画面来自本轮真实运行截图，配音使用 Windows 中文合成语音；不是连续实操录像。

## 0:00—0:35 定位与边界

欢迎观看 TraceRisk 授信前调查演示。本项目服务于金融机构的调查人员和复核人员，调查对象是中小企业。本段画面来自本轮实际运行的合成演示页面，采用截图讲解方式。我们使用确定性规则、证据分析、人工复核和不可变报告来组织调查资料。企业和证据均为合成样本，并未接入真实工商或司法服务。本项目不计算授信额度，不审批贷款，也不预测违约概率。

## 0:35—1:15 企业身份与调查基准日

首先在企业详情核对企业名称和统一社会信用代码，再选择调查基准日。同一企业在不同基准日可能有不同事实，因此不能混用不同调查的评分。详情页面列出该企业既有调查，可以进入对应日期的风险画像，或打开已经形成的报告。本次典型案例为远景精工合成企业，基准日固定为二零二六年九月十一日。点击创建调查后，后台队列执行检索和分析；这里的页面截图来自真实队列运行，而不是界面中预先写好的成功结果。

## 1:15—2:25 规则分、覆盖与证据

调查画像把规则分和证据覆盖放在一起展示。司法存在未结案件加三十五分；基准日仍有效的经营异常加二十五分；基准日前含当日三百六十五天内，至少两条独立负面报道加二十分；核心专利失效或存在权属争议加十五分。每条规则最多计分一次，总分最高九十五分，重复案件和新闻转载不会重复计分。零到二十九分为演示低风险，三十到五十九分为中风险，六十到九十五分为高风险。本例命中四条规则，得到九十五分。这些权重只是演示配置，并不是金融机构信用标准。模型和复核人员都不能改动规则分。向下查看具体规则，可以通过引用打开本次检索的原文片段，核对来源、观察日期、事实键和内容版本。引用归属、哈希和连续摘录经过硬校验，不能把已结案件作为未结案件的支持证据。

## 2:25—3:30 缺失与人工复核

第二个场景展示信息不足的企业。虽然规则分是零，但画像显式提示，来源不足或覆盖未确认，零分不代表企业安全。缺少事实不会直接增加负面分值，来源不足会单独触发人工复核。跨来源冲突、高分、模型证据不足、建议复核，以及无法确认支持程度的自然语言扩展，也会进入人工处理。没有模型发现的调查支持运行级复核。有发现时，复核人员可批准、修改或驳回；修改形成独立版本，原始模型内容仍保留。分析员不能自行批准自己创建的调查。特别要注意，人工复核不能绕过引用硬校验。模型调用、引用或声明支持性校验失败时，运行显示失败原因和重新调查入口，不会输出伪成功报告。

## 3:30—5:00 不可变报告与实测限制

复核完成后，后台恢复流程，生成不可变报告。报告保留调查日期、企业身份、规则结果、原始模型发现、人工决定、最终发现，以及证据、来源和版本信息。模型来源依据实际保存的调用记录展示；未保存来源的历史报告明确显示未记录，不能用今天的环境配置推断过去的模式。本轮八类浏览器路径全部通过，包括低风险、高风险复核、修改、驳回、来源冲突、来源缺失、非法引用拒绝和重复恢复。真实模型也经生产接口和队列完成一次九十五分合成调查、复核提交及报告生成；其中的复核是自动化协议验证，不是真人业务核验。独立二十例真实调用中，应复核案例只有五例中的两例成功进入复核，另三例因声明支持性硬校验失败而拒绝，不能把这种结果表述为全部正确。历史四十例响应离线回放中，应复核成功从一例增加到九例，仍有一例硬拒绝，并增加了十五例保守复核。成本仅有基于用量和冻结价格的估算，没有账单数据。真实金融效果、领域专家标签复查和授权样本试点仍需后续落实。
