# 展示版六页文案

按最新要求用于比赛展示，允许合成与改编样例，不以真实资料接入为前提。六张完整16:9页面见 slides/，可直接插入PPT；统一标注“演示样例，仅作功能展示”。技术答辩细节见 detailed-speaker-notes.md。

## 1｜知识库：把分散材料变成调查依据

上屏：工商经营、司法诉讼、新闻舆情、知识产权四类证据。保存主体、时间、状态、来源与内容指纹；规则配置与企业事实分开，调查结论能找到依据。

讲述：知识库把资料整理成可筛选、可引用的企业事实。规则负责确定性判断，模型辅助解释。

## 2｜从一份材料到一份报告

上屏：资料整理 → 字段提取 → 片段索引 → 检索引用 → 人工复核 → 报告归档。

示例：“某企业案件未结”→ 案号、状态与日期 → 司法规则命中 → 引用原文 → 人工核实 → 保存报告。

讲述：围绕一次调查，资料、模型发现和人工决定保留关联；查看结论时可以回到对应证据。这是演示流程示意，不声称本批真实资料已接入。

## 3｜问题理解：四个问题对应四项设计

| 问题 | 设计 |
|---|---|
| 材料分散，查找耗时 | 统一来源与证据结构 |
| 同名企业、历史状态混淆 | 企业标识与调查基准日约束 |
| 模型解释缺少依据 | 冻结引用与支持校验 |
| 资料不足、来源说法不一致 | 显式警示与人工复核 |

讲述：目标是授信前调查辅助，输出事实、规则命中、待核实事项和复核建议，帮助调查人员组织判断。

## 4｜逻辑论证：用反例检查流程

上屏：明确事实、跨企业干扰、时间更新、跨源冲突、来源缺失、错误引用，六类场景各两例。

- 本企业的有效事实，才能支持本次调查。
- 新状态应替代旧状态，跨源冲突需保留说明。
- 缺资料提示补充，错误引用阻止放行。

讲述：12例构成展示验证设计，通过成功和失败场景说明机制。该矩阵未新运行，不称生产v2质量评测；历史数据图在figures/中作为答辩备图，陈旧事实反例保留在备查文档中。

## 5｜结果解读：95分是怎样得到的

上屏：经营异常25 + 司法未结35 + 负面新闻20 + 核心知识产权异常15 = 95。

阅读顺序：看规则命中 → 看证据覆盖 → 看原文引用 → 看复核决定。

讲述：示例为远景精工（合成）有限公司。95分是演示规则全部命中的累计值；事实与AI解释分开呈现，报告保留复核记录，分数不等于违约概率。

## 6｜不同结果，对应不同下一步

| 演示结果 | 下一步 |
|---|---|
| 多项规则命中 | 打开证据，核实状态与关键事实 |
| 零分但来源不足 | 补查资料，记录限制并转复核 |
| 案件结案或进入执行 | 更新状态，继续核实回款与追偿进展 |

价值表达：证据更容易查找，遗漏和分歧更容易被看见，复核与报告更容易追溯。

讲述：重点是让每种结果引导下一步操作。展示不预设节省时间比例；真实业务效果留待试用测量。
