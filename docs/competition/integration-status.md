## 已读约束与最小实现取舍

- `companies.unified_credit_code` 必填且唯一；只读闸门还要求非空18位允许字符及MOD 31校验位，结构有效不代表注册身份已经核实；不放宽企业主表，不新建伪身份。
- `Evidence` 要求企业外键、合法来源/风险类别、64位内容哈希、同企业 source_uri 唯一。不能给同公告的多条证据复用完全相同 source_uri；未来应以原文URL加稳定片段定位形成证据URI，另保留原文URL与页码。包内同摘录随案例复用的记录还需去重，不能按案例数导入重复事实。
- `chunk_evidence` v1 对司法证据生成单片段，ID由 evidence ID + v1 + ordinal 决定；新闻按空段分片。正文内容摘要与片段哈希分别保存。
- 索引要求512维、cosine、v1；使用现有 BGE `BAAI/bge-small-zh-v1.5`。`build_index` 不提交，由调用方持事务，使用激活锁；不覆盖历史片段或冻结检索。`index_cli --provider` 仅支持 `fake|bge`，本身不校验数据库所有权，不能在默认库直接运行。
- `evidence.service` 在选择时冻结企业、基准日、检索索引、查询和片段哈希；当前工作流使用四类固定风险查询。10条问句探针与固定工作流查询是两种检验，后续必须明确分别运行。
- `database_lifecycle` 只允许精确匹配运行所有权的 `tracerisk_eval_<32hex>` / `tracerisk_e2e_<32hex>` 删除，已有同名库拒绝认领；生命周期初始化限定 Mock/Fake，会种合成目录，不能直接拿来声称真实样本初始化。未来需先创建并保存 owned handle、核验 current_database，再在该库迁移和导入；随后显式构建真实BGE索引。
